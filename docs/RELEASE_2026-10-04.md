# 타이니 툰 어드벤처스 한글 패치 v1.0 배포 묶음

**2026-10-04 작업17 최신:** 당근30개 교환 후 공통 작별 대사의 대기 중 폰트가 먼저 바뀌는 오류를 재현·수정했다. ‘몇’의 획도 분리했다. [원인·검증·재현](HAMTON_FONT_FIX_2026-10-04.md), [v1.0.1 ZIP](../dist/TinyToonAdventures_KR_Patch_v1.0.1_20261004.zip)을 따른다. 이전006/작업16 검증은 이 대기 구간의 오류를 놓쳤으며 아래 기록은 이력이다.


사용자 요청에 따라 기존 게임 배포 폴더와 같은 xdelta 구성으로 릴리즈를 작성했다. 최신 [배포 폴더](../dist/TinyToonAdventures_KR_Patch_v1.0_20261004), [ZIP](../dist/TinyToonAdventures_KR_Patch_v1.0_20261004.zip), [ZIP 체크섬](../dist/TinyToonAdventures_KR_Patch_v1.0_20261004.zip.sha256)을 사용한다. ZIP 크기는175,896바이트다.

공개 게시용 글은 [RELEASE_NOTES_KO.md](../dist/TinyToonAdventures_KR_Patch_v1.0_20261004/RELEASE_NOTES_KO.md), 사용법은 [README_적용방법.txt](../dist/TinyToonAdventures_KR_Patch_v1.0_20261004/README_적용방법.txt)에 있다. 파일과 안내를 작성했으며 외부 사이트에 업로드하지 않았다.

## 기존 배포 형식과 같은 구성

```text
TinyToonAdventures_KR_Patch_v1.0_20261004/

```

원본/완성 ROM·추출 이미지·폰트PNG/TTF·에뮬레이터·장면 스킵 도구는 포함하지 않는다. Windows x64에서 기본 PowerShell과 동봉 xdelta3만으로 적용하며 Python은 필요 없다. ZIP은 기존 배포본처럼 하나의 릴리즈 폴더를 루트로 포함한다.

## 적용과 내용

지원 일본판 원본 `.nes`를 `apply.cmd`에 끌어다 놓으면 원본 옆에 `<원본 파일명>_KR.nes`가 생긴다. 원본과 기존 결과를 덮어쓰지 않는다. 원본 크기/해시, 패치/도구 해시, 결과 크기/해시를 확인하며 다른 판본과 이미 패치한 ROM을 거부한다.

한국어 타이틀 로고, 사용자 제공 일본어 대사22블록(도입부6·햄튼5·선택/추천7·엔딩4), Galmuri7 8×8을 포함한다. 기존 영문 및 스태프롤은 유지했다. 원본에서 검증된006으로 가는 단일 패치이며 이전 IPS를 먼저 적용하지 않는다.

| 대상 | 크기 / SHA-256 |
|---|---|
| 지원 원본 | 262,160바이트 / `73300dc1505564827ef95ba3e2a06c26aa48920e4981195f32b2101c185ef3dd` |
| 결과 ROM | 524,304바이트 / `6d834cdde925dd808ef6d911ebf2f13f5a88e440c9da4bfc50b424035309483d` |
| xdelta 패치 | `7f794b3f6cc358fee94a5348bd9946a0afd7f4c113940f9346ad91873dd91e27` |
| 배포 ZIP | `d88894a72dc3beef16612e8346307d8e0310af8a6eb2ff7dee688fc05a726d7d` |

## 검증을 구분한 결과

- 정적/빌드: 기존006의7개 Expected Write·원문보존·글리프/줄·604인코딩벡터·읽기/폰트/뱅크/IRQ 모델·2048모드0 보호·재빌드/IPS 적용PASS를 재사용했다. 목표 ROM과 CSV/등록 폰트/보호입력 해시가 같은지 확인했다. ROM을 수정하지 않았다.
- 새 배포 적용: 한글/공백 경로에서 실제 `apply.cmd`→PowerShell→동봉xdelta 실행, 정상 적용·기존 결과 거부·원본과 결과 같은 경로 거부·같은 크기의 잘못된 원본 거부·패치된ROM 재적용 거부·손상패치 거부·손상도구 거부·인수없음 처리의8검사PASS다. 결과를006과 바이트 단위 대조했고 원본 불변을 확인했다. [실제 적용 보고서](<../qa/apply/릴리즈 한글 경로 검증 20261004_001/apply_verification.json>)를 따른다.
- 최종ZIP: CRC,11파일 허용 목록, 폴더와 압축파일 내부 바이트/체크섬 일치를 확인했다. **최종 ZIP을 한글/공백 경로에 풀어 다시 적용**, 결과가006과 바이트 단위로 같고 배포 파일이 변하지 않음을 확인했다. [최종 배포 검사](../qa/reports/release_TinyToonAdventures_KR_Patch_v1.0_20261004_final.json)와 [묶음 내 보고서](../dist/TinyToonAdventures_KR_Patch_v1.0_20261004/release_report.json)를 따른다.
- 에뮬레이터/시각: 동일 ROM의 기존 Mesen2.1.1 정상 도입부·선택·햄튼30개 교환/별도29개 분기, [선택6장면·실제엔딩4문단/스태프롤](DIALOGUE_SCENE_QA.md)을 재사용한다. 선택/엔딩은 선언RAM스킵,631표본 텍스트밖차이0 및 별도 직접시각PASS다. ZIP 작성이새게임실행검증을 뜻하지 않는다.

번역은 사용자 제공본 그대로이며22개`needs_review`를 변경하지 않았다. 사용자의 릴리즈 작성 지시에 따라 배포 묶음을 만들었고 최종 사람 문구/화자 검토 완료로 표기하지 않았다. 전체완주/보스승리·실기·다른에뮬레이터·전게임RAM조사는미수행이며이번대사QA의새필수조건으로추가하지않는다. v1.0은배포버전명이다.

## 재현과 보존

[빌더](../scripts/make_release_dist.py)는 기존 원본/006/입력/QA·릴리즈템플릿, 공용Tools의xdelta3.2.0 실행파일/README와 기존Death Jr 배포용 도구LICENSE를 사용한다. 처음부터 새 배포 폴더와 새 QA 폴더를 지정한다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\verify_source.ps1
python .\scripts\make_release_dist.py --name TinyToonAdventures_KR_Patch_v1.0_20261004_repro_next --qa '.\qa\apply\릴리즈 재현 next'
```

`--finish`는 실제8검사를 통과한 기존 미봉인 묶음만 해시 재확인 후 마무리하는 복구 경로다. 완성ZIP/보고서는 덮어쓰지 않는다. 표준 배포 모양은 기존City Connection/Metroid Fusion/Death Jr의 폴더 구성을 직접 대조했다.

초기 준비 중 기본문자셋 읽기/한글파일명 체크섬 쓰기를UTF-8로 고쳤고, 버전명의점이파일접미사로해석되어축약된ZIP명이생긴것을정정했다. 축약명 `TinyToonAdventures_KR_Patch_v1.zip`과 중간검사/QA는보존하지만최신으로안내하지않는다. 정식전체이름ZIP과바이트는동일하다. 기존테스트002/이전빌드·모든QA·원본·CSV·폰트를보존했고삭제하지않았다.
