## 1. 목표와 권장 전략

> **2026-10-01 작업 4 사용자 확정 — 기존 계획보다 우선 적용:** 이미 제작한 한글 게임명 로고는 보존한다. `PUSH START`를 포함한 영문 UI·효과음·게임 오버 그래픽 등의 추가 번역은 하지 않고 원문을 유지한다. 아래 계획의 ‘시작 안내 한글화’는 해당 안내가 영문인 경우 적용하지 않는다. 일본어 대사·안내 번역은 사용자가 다른 AI와 진행한다. 현재 세션은 인계 문서 갱신 후 종료했으며 자동으로 후속 조사·번역·빌드를 실행하지 않는다. 최신 재개 지시는 docs/HANDOFF_2026-10-01.md의 작업 4를 따른다.

**타이틀은 로고 타일과 화면 배치를 수정하고, 인게임 자막은 실제 문자 표시 경로를 확인한 뒤 한글 폰트·문자표·문장을 함께 수정한다. 두 경로의 한글 표시 PoC를 각각 통과시킨 뒤 전량 작업한다.**

이번 계획 수립에서는 원본 해시, 헤더, 전체 CHR 타일의 정적 디코딩을 확인했다. 타이틀·일본어 글자 후보도 찾았다. 아직 에뮬레이터 화면과 연결하지 않았으므로 후보 주소를 바로 패치 위치로 채택하면 안 된다.

| 작업 | 범위 | 우선 접근 | 완료를 판단할 증거 |
|---|---|---|---|
| 타이틀 한글화 | 게임명 로고 및 타이틀 화면의 시작 안내 | 기존 CHR 타일·네임테이블·속성표 수정 | 콜드 부팅부터 한국어 로고 표시, 대기·입력·게임 시작·복귀 정상 |
| 인게임 자막 한글화 | 실제 존재하는 대사, 이야기 설명, 진행 안내, 힌트, 엔딩 문구 | 원본 문자 소비 방식 재사용 + 필요한 한글 음절 공급 | 대상 목록 전수 대응, 실제 장면의 가독성·페이지 전환·이벤트 진행 정상 |

- 여기서 자막은 원작에 존재하는 화면 문구를 뜻한다. 없는 대사나 외부 영상 자막을 새로 추가하지 않는다.
- 타이틀 표기 기본안은 **‘타이니 툰 어드벤처’**이다. 로고 공간에 따라 ‘타이니 툰’ / ‘어드벤처’의 두 줄 배치를 먼저 검토한다. 이는 제작 시작안이며 사용자 승인 완료안으로 표현하지 않는다.
- 회사 로고, 저작권 표기, 캐릭터와 배경 그림은 보존한다. HUD 숫자·점수, 영문 효과음, 게임 오버 그래픽 등은 목록에 기록하되 요청 범위와의 관계를 판정한 후 처리한다. 대사와 무관한 UI 전체 개편으로 확대하지 않는다.
- 기본 구현은 ROM에 반영되는 한글 패치다. 에뮬레이터 전용 HD팩·화면 오버레이·스크린샷 합성을 완성품으로 제출하지 않는다.

## 3. 확인된 원본과 분석 근거

### 3.1 로컬 파일에서 확인한 사실

| 항목 | 확인값 |
|---|---|
| 원본 상대 경로 | `original/rom/Tiny Toon Adventures (Japan).nes` |
| 전체 크기 | 262,160 bytes (`0x40010`) |
| SHA-256 | `73300dc1505564827ef95ba3e2a06c26aa48920e4981195f32b2101c185ef3dd` |
| 원시 헤더 | `4E 45 53 1A 08 10 70 10 00 00 00 00 00 00 00 00` |
| 헤더 형식 | iNES 1.0, 서브매퍼 정보 없음 |
| 매퍼 번호 | 23 (`0x17`) |
| PRG-ROM | 128 KiB, 파일 오프셋 `[0x00010, 0x20010)` |
| CHR-ROM | 128 KiB, 파일 오프셋 `[0x20010, 0x40010)` |
| trainer | 없음 |
| 헤더 battery / four-screen 비트 | 둘 다 0; 실제 RAM 사용 여부를 이 값만으로 확정하지 않음 |
| CHR 정적 검사 | 8,192개 타일, 32개 4KiB 보기 페이지; 전체 decode→encode 바이트 일치 |
| 실행·장면 검증 | 미수행 |

주소 범위의 오른쪽 끝은 포함하지 않는다. 헤더 길이와 데이터 배치는 [iNES 형식 자료](https://www.nesdev.org/wiki/INES)에 따라 해석했다. 파일명 ‘Japan’만으로 정확한 리비전이나 정상 덤프 여부까지 확정하지 않는다.

NESdev에는 Tiny Toon Adventures (J)가 VRC4e / mapper 23으로 정리돼 있다. 이는 조사 방향을 정하는 외부 근거이며, 현재 덤프의 보드 배선·주소 디코드·IRQ 사용이 역공학으로 확정됐다는 뜻은 아니다. 해당 매퍼 계열은 PRG/CHR 뱅크 전환을 사용하므로 CPU 주소와 파일 주소를 구분해야 한다. [VRC2/VRC4 자료](https://www.nesdev.org/wiki/INES_Mapper_023)

### 3.2 실제로 확인한 타일 후보

다음은 **원본 CHR를 그레이스케일로 디코딩한 결과**다. 게임 화면을 캡처한 것이 아니며 원래 팔레트·배치를 재현하지 않는다.

| 후보 ID | 보기 페이지 / 파일 범위 | 이미지에서 확인한 내용 | 아직 확인하지 못한 것 |
|---|---|---|---|
| TITLE-CHR | `0x0E` / `[0x2E010, 0x2F010)` | 게임명 로고 조각, 시작 안내·저작권 표기처럼 보이는 조각 | 타이틀의 실제 사용 타일·배열·팔레트·공유 여부 |
| DIALOG-KANA | `0x1E` / `[0x3E010, 0x3F010)` | 상단에 히라가나·기호 글자군, 주변에 캐릭터·배경 조각 | 본문에 쓰는 코드표, 실제 CHR 뱅크, 글자 수·셀 크기·문장 위치 |
| LATIN-UI | `0x12` / `[0x32010, 0x33010)` | 숫자·영문·기호 및 다른 그래픽 | 자막과의 공유 여부, 보호해야 하는 UI |
| KATAKANA | `0x1A` / `[0x3A010, 0x3B010)` | 일부 가타카나·기호와 배경 조각 | 이름·대사·UI 중 어디에 쓰이는지 |

4KiB 페이지는 이번 분석 도구의 보기 단위다. 런타임 뱅크나 수정 허용 범위와 동일하지 않다. 특히 문자와 비문자 그림이 같은 페이지에 섞여 있으므로 **페이지 전체 교체를 금지한다.**

## 4. 절대 지켜야 할 규칙

1. 원본 ROM을 수정·삭제·덮어쓰기하지 않는다. 매 작업 전 원본 해시를 검증한다.
2. 타일 후보·문자처럼 보이는 바이트열·외부 공략을 확정 주소나 확정 대사로 취급하지 않는다.
3. 파일 오프셋, PRG 상대 오프셋, CPU 주소, CHR 상대 오프셋, PPU 주소를 이름과 필드로 구분한다.
4. 변경할 모든 바이트를 Expected Write에 등록한다. 최소 필드는 작업 소유자, 이유, 파일 오프셋, 기대 원본 바이트/해시, 최종 바이트, 허용 길이이다. 충돌·미등록 diff·범위 초과는 빌드 실패다.
5. `00`/`FF` 반복이나 한 번의 미참조 관측만으로 빈 공간·미사용 문자 슬롯을 선언하지 않는다.
6. 원문의 인물, 힌트, 조건, 수치, 말투를 보존한다. 수용량 부족을 이유로 임의 삭제하거나 의미를 줄이지 않는다. 먼저 저장·배치·폰트 공급 대안을 평가한다.
7. 종료·대기·화자·이벤트 제어코드를 임의로 삭제하지 않는다. 모르는 토큰은 원시 바이트로 보존하고 수정 가능한 경계부터 확인한다.
8. 최신 검증 빌드와 QA 증거를 보존한다. 작업 종료 시 성공·실패 여부와 무관하게 handoff를 갱신한다.

ASM 훅이 필요해지면 NES CPU에 맞는 검증된 어셈블러·디스어셈블러를 사용하고 원본 명령 경계, 레지스터·플래그·스택, 복귀 주소, NMI/IRQ와 뱅크 상태를 검증한다. 패치에 필요한 명령 몇 개만 지원하는 자체 도구로 명령 이동의 안전성을 주장하지 않는다.

## 5. 공통 선행 조사 — 작업 A

### A1. 원본 실행 환경과 화면 목록 확보

- 원본 확인 스크립트를 실행하고 에뮬레이터 실행 파일 경로·버전·실제로 연 ROM 경로 및 해시를 기록한다.
- Mesen 계열처럼 CPU 디버거, CHR/네임테이블/팔레트 확인, 메모리 쓰기 추적을 지원하는 도구를 사용한다. 설치된 버전에 맞춰 메뉴/API를 확인한다. 기존 Mesen 공식 문서의 PPU Viewer는 이런 관측 기능을 설명한다. 해당 문서는 0.9.9 기준이므로 메뉴명을 최신판에 그대로 강제하지 않는다. [Mesen PPU Viewer](https://www.mesen.ca/docs/debugging/ppuviewer.html)
- 원본 콜드 부팅 → 타이틀 → 첫 대사/안내가 나오는 장면까지 관측한다. 이어서 실제로 존재하는 스테이지 진입·클리어·실패·계속하기·엔딩 등의 문구를 조사한다. 해당 장면이 없으면 근거와 함께 ‘없음’으로 기록한다.
- 화면마다 `scene_id`, 진입 입력 순서, 프레임/이벤트 지점, 스크린샷, 텍스트 영역, 문자열/그래픽/혼합 여부, 등장 조건을 남긴다.
- 저장 상태는 같은 ROM·같은 에뮬레이터 버전에 귀속시킨다. 이후 패치의 초기화 검증은 원본에서 만든 저장 상태에 의존하지 않는다.

### A2. 화면에서 ROM으로 역추적

- 타이틀과 대표 자막 화면에서 네임테이블, CHR 매핑, 속성표·팔레트를 저장한다. 스프라이트 글자가 있으면 OAM도 조사한다.
- 타일 번호를 원본 CHR 후보와 대조하고 PPU 주소 → 활성 1KiB CHR 뱅크 → ROM 파일 위치를 연결한다. 프레임 중간에 뱅크가 바뀌면 스캔라인도 기록한다.
- 네임테이블을 갱신하는 `$2006/$2007` 접근 등을 추적해 CPU 측 원본 데이터 읽기·RAM 버퍼·전송 루틴까지 거슬러 올라간다. 이 레지스터 번호는 PPU 관측 출발점이며 게임별 훅 주소가 아니다.
- PRG 뱅크 전환과 CPU 창을 함께 기록한다. 8KiB 창으로 확인된 경우에만 `file = 0x10 + physical_bank * 0x2000 + (cpu - window_base)`를 적용한다. 고정 창과 전환 모드도 별도로 검증한다.
- 1KiB CHR 뱅크 매핑으로 확인된 경우 `file = 0x20010 + chr_bank * 0x400 + offset_in_bank`를 쓸 수 있다. 전체 CHR 오프셋과 PPU의 타일 번호를 혼동하지 않는다.

### A 완료 조건

타이틀과 대표 자막 각각에 대해 **화면 → 타일/코드 → 활성 뱅크 → 원본 파일 위치 → 소비 루틴**을 연결한다. 확인하지 못한 부분은 정확히 남긴다. 첫 실행에서 대사 화면이 보이지 않는다고 ‘인게임 텍스트 없음’으로 결론 내리지 않는다.

예정 산출물: `docs/ARCHITECTURE.md`, `docs/SCENE_CATALOG.md`, `qa/reports/qa_environment.json`, 화면·트레이스 증거. 이 파일들은 계획상 신규 산출물이며 현재 존재하지 않는다.

## 6. 타이틀 한글화 — 작업 B

### B1. 구성 요소와 공유 관계 확정

1. TITLE-CHR 후보를 실제 타이틀에 대응시킨다. 게임명, 시작 안내, 회사/저작권, 배경, 캐릭터를 별도 블록으로 분류한다.
2. 블록별 화면 좌표·크기, 사용 타일 목록, 네임테이블 위치, 속성·팔레트, 타일 재사용 위치를 기록한다.
3. 반복 사용되는 하나의 타일을 서로 다른 한글 조각으로 바꿔야 한다면 타일 복제와 네임테이블 수정이 필요하다. 사용 가능한 슬롯부터 실측한다.
4. 타이틀 배치 데이터가 압축·명령 스트림이면 원본 해제 경계와 소비자를 확인하고 무변경 재삽입을 먼저 통과시킨다.

### B2. PNG 시안과 타일 예산

- 실제 화면 배치·팔레트로 원본 타이틀을 재구성한 뒤 한국어 게임명과 시작 안내 시안을 만든다. 빈 타일 모음에 글씨만 쓰는 것으로 화면 시안을 대신하지 않는다.
- 게임명 기본안 ‘타이니 툰 어드벤처’를 기존 작품 분위기와 대비를 유지하는 픽셀 로고로 배치한다. 시작 안내의 정확한 원문·동작을 확인한 뒤 자연스러운 한국어로 옮긴다.
- 원래 그림·색을 보호할 마스크와 한글 수정 허용 영역을 정한다. 사용 가능한 색·슬롯 안에서 조판하고, 확대 PNG와 네이티브 해상도에서 판독성을 모두 확인한다.
- NES의 8×8 타일은 16바이트이며 배경 팔레트 선택은 보통 16×16 영역 단위의 제약을 받는다. 이를 무시한 임의 색상이나 안티앨리어싱 이미지를 그대로 넣지 않는다. [PPU 패턴 형식](https://www.nesdev.org/wiki/PPU_programmer_reference), [속성표](https://www.nesdev.org/wiki/PPU_attribute_tables)
- 시안별 고유 타일 수, 기존 로고 전용 슬롯 수, 추가 슬롯 수, 바뀌는 배치·팔레트 바이트를 수치로 비교한다. 원본 로고 전용 슬롯 안에서 가능한 안을 먼저 검토한다.

### B3. 대표 한글 로고 PoC

- 실제 타이틀 경로에 짧은 한국어 로고/일부 글자를 넣어 저장된 바이트가 화면에 도달하는지 확인한다. 최종 전체 로고 제작 전에 공유 타일·팔레트·반복 배치 위험을 해소한다.
- 원본 기준으로 `build/<빌드ID>/`에 새 ROM을 만들고 해시와 Expected Write 보고서를 남긴다.
- 콜드 부팅, 대기 시 변화, 시작 입력, 게임 진입, 타이틀 재진입/리셋에서 로고 유지와 배경·캐릭터·음악·입력 정상 여부를 확인한다.
- 통과 후 전체 로고 및 시작 안내를 같은 경로로 적용한다. 원본 로고 애니메이션이나 별도 스프라이트 층이 있다면 모든 변형을 포함한다.

### B의 대안 선택

| 관측된 제약 | 다음 선택 | 추가로 입증할 것 |
|---|---|---|
| 로고 슬롯과 배치가 충분함 | 기존 타일과 필요 배치만 교체 | 공유 그림 불변, 목표 외 픽셀 불변 |
| 반복 타일 때문에 다른 글자 조각이 충돌함 | 전용 타일 복제 + 배치 수정 | 새 슬롯의 전체 소비자와 수용량 |
| 현재 CHR 뱅크 안에 부족함 | 타이틀 전용 뱅크 배치 또는 검증된 CHR 확장 검토 | 매퍼 주소 가능 범위, 선택 코드, 다른 화면 재진입 |
| 배치 데이터 재압축이 필요함 | 원본 소비자 호환 재압축 경로 구현 | 무변경 왕복, 길이·포인터·해제 범위 |

타이틀 로고는 본문 문자 코드 공간을 무리하게 공유할 필요가 없다. 두 작업이 같은 CHR 뱅크나 타일을 수정하는 경우에만 통합 소유권을 먼저 정한다.

예정 산출물: `workspace/graphics/title/`, `manifests/title_assets.json`, 재현 가능한 추출·삽입 스크립트, `docs/POC_TITLE.md`, 타이틀 검증 빌드와 QA 증거.

## 7. 인게임 자막 한글화 — 작업 C

### C1. 자막의 실제 저장 형태 분류

대표 화면부터 DIALOG-KANA, KATAKANA, LATIN-UI 후보를 연결한다. 한 화면을 확인한 문자표를 다른 화면에 자동 적용하지 않는다.

| 실제 관측 | 구현 방향 |
|---|---|
| 문자 코드 → 타일 번호 → 네임테이블 표시 | 코드표와 폰트 교체, 문자열 재삽입 |
| 문자열 없이 완성된 타일맵/그래픽을 표시 | 문구별 그래픽·타일맵 번역; 화자·진행 제어는 보존 |
| 문자열과 장식/이미지 문구가 혼재 | 두 경로를 목록에서 분리하고 각자 검증 |
| 압축 또는 조합 코드가 있음 | 파서·소비자 및 무변경 왕복을 먼저 확정 |

일본어를 Shift-JIS·UTF-8로 가정하지 않는다. 글자 타일의 정렬 순서도 저장 코드표와 동일하다고 가정하지 않는다. 탁점·반탁점·작은 글자·기호가 조합되거나 별도 제어될 수 있으므로 표본을 포함한다.

### C2. 원문·제어코드·참조를 가역 추출

다음 정보를 갖는 원문 데이터와 번역 입력을 분리한다.

- 안정 ID, 장면 ID, 화자·상황, 원본 리비전 해시.
- PRG 파일 오프셋, 활성 뱅크, CPU 주소, 원시 바이트, 실제 참조 위치.
- 원문, 종료·줄바꿈·페이지·대기·화자·이벤트 토큰과 인자.
- 코드표 ID, 경계 결정 근거, 길이 제한, 창 크기, 화면 캡처 경로.
- 한국어 초안, 검토 상태, 최종 번역, 비고.

원문은 `extracted/text/`, 사람이 편집하는 번역의 단일 원천은 `workspace/translation/`에 둔다. JSON/JSONL 등으로 저장하되 필드·검증 규칙을 문서화한다. 한국어 UTF-8은 작업 파일의 표현일 뿐 ROM 인코딩이 아니다.

포인터는 실제 소비자의 폭·기준·뱅크 규약으로 확정한다. 같은 문자열을 여러 곳이 참조하거나 중간부터 읽는 경우를 보존한다. 다음 포인터까지의 간격을 무조건 문자열 길이로 삼지 않는다.

**번역을 넣기 전에 원문 추출→재삽입 결과가 원본과 일치해야 한다.** 타이밍이나 이벤트가 바뀌지 않는지도 대표 장면에서 확인한다. 왕복 통과만으로 추출 누락이 없다고 주장하지 않는다.

### C3. 한글 폰트와 코드 공간 선택

우선순위는 **기존 표시 경로를 쓰는 완성형 음절 공급 → 장면별 CHR 뱅크/코드표 활용 → 필요성이 입증된 표시 루틴 확장**이다. 수요 측정 전에 방식이나 최대 한글 수를 고정하지 않는다.

1. 원문 목록과 의미를 보존한 초벌 번역에서 전체 고유 음절, 장면별 고유 음절, 동시에 보이는 음절·기호를 집계한다.
2. 실제 사용 중인 숫자·영문·구두점·UI·배경·제어값을 예약한다. 회수 가능한 글리프와 타일 슬롯만 공급량에 넣는다.
3. 원본 셀이 8×8로 확인되면 작은 한글 폰트 후보를 같은 배경·팔레트에서 비교한다. 작게 보인다는 이유로 처음부터 16×16을 선택하지 않는다.
4. 8×8의 받침·겹받침·복합 모음이 읽히지 않으면 8×16 또는 16×16을 검토한다. 한 글자가 여러 타일을 쓰면 커서 증가량, 창 폭, 행 간격, 줄바꿈, 페이지 수, 지우기·전송량까지 함께 바뀐다.
5. 필요한 글자만 제공하는 완성형 부분집합부터 설계한다. 현대 한글 전체 11,172자를 무조건 저장하지 않는다. 다만 최종 코퍼스와 실제 동적 삽입값의 누락은 0이어야 한다.
6. 폰트는 출처·버전·라이선스를 확인하고 고정된 변환 설정으로 만든다. 폰트 이름만으로 해당 셀의 가독성을 보장하지 않는다.

예산은 아래 항목을 분리해 계산한다.

| 예산 | 계산·검토 기준 |
|---|---|
| ROM 저장 | 전체 글리프의 타일 데이터 + 매핑표 + 문자열 성장량 |
| 코드 공간 | 실제 파서가 문자로 읽는 값에서 제어·예약값을 제외한 수 |
| 활성 CHR 슬롯 | 해당 화면에서 한글·기호·UI·배경이 동시에 필요로 하는 타일 수 |
| 화면 배치 | 실제 텍스트 상자의 열·행·픽셀 폭 및 페이지 동작 |
| 실행 비용 | 추가 코드, 뱅크 전환, 전송 루틴의 시간 및 이벤트 영향 |

계산 출발점: 8×8 글리프 1타일은 16바이트, 8×16은 2타일로 32바이트, 16×16은 4타일로 64바이트이다. 이는 저장량 계산이며 사용 가능한 슬롯 수나 글리프 인덱스 규약을 뜻하지 않는다. 한 1KiB CHR 뱅크에는 64개 8×8 타일이 들어가지만 그 전부가 자막용이라고 가정하면 안 된다.

**현재 원본은 CHR-ROM을 갖는다.** ‘한글을 매 프레임 CHR에 업로드’하는 CHR-RAM 전용 해법을 그대로 적용하지 않는다. 장면별 글리프를 바꾸려면 현재 하드웨어에서 선택 가능한 ROM 뱅크와 실제 표시 중인 슬롯을 사용해야 한다. 다른 카트리지 구성이나 RAM을 요구하는 설계는 기본안에 섞지 않고 별도 호환성 변경으로 평가한다.

| 측정 결과 | 선택 후보 | 통과 조건 |
|---|---|---|
| 전체 음절이 확인된 전용 슬롯·코드에 들어감 | 고정 완성형 글리프 교체 | 모든 문장·UI 공유 경로에서 동일하게 해석 |
| 전체는 넘지만 장면별 집합은 들어감 | 장면별 CHR 뱅크/문자표 | 보이는 글자가 사용 중 다른 글리프로 바뀌지 않음; 재진입·페이지 전환 정상 |
| 한 화면 집합부터 부족함 | 셀·뱅크 배치 조정 또는 페이지 레이아웃 확장 | 문장 의미·타이밍·표시 수명 보존 |
| 코드 공간·문장 저장이 부족함 | 명시적인 확장 코드/포인터 재배치 | 모든 소비자 갱신, 원본 토큰 충돌 0, 저장·뱅크 제약 통과 |
| 기존 방식으로 해결되지 않음 | 조합형 등 새 렌더러 검토 | CPU·메모리·카트리지 제약 안에서 합성 및 표시 가능함을 먼저 입증 |

16비트 코드나 조합형은 기본 전제가 아니다. ROM 크기만 키워도 더 많은 글자가 보이는 것이 아니며, 뱅크 레지스터·마스킹·포인터·화면 슬롯까지 연결돼야 한다.

### C4. 대표 자막 E2E PoC

- 실제 존재하는 대사/안내 한 블록을 고른다. 가능하면 긴 문장, 페이지/대기 제어, 받침·복합 모음이 있는 자연스러운 한국어를 포함한다.
- 이 블록에 대해 원문 추출 → 초벌 번역 → 글리프 생성 → 코드 매핑 → 재삽입 → 패치 ROM 실행을 하나의 재현 경로로 통과시킨다.
- 글자 표시뿐 아니라 표시 속도, 기다림, 줄/페이지 전환, 지우기, 화자·초상, 입력, 다음 이벤트를 확인한다.
- 장면별 뱅크 교체를 채택했다면 앞 장면 → 대상 장면 → 다음 장면 → 재진입을 확인한다. 글리프가 화면에 남아 있는 동안의 교체 충돌을 검사한다.
- 실패하면 문자 위치·타일 매핑·뱅크 선택·박스 크기·토큰 해석 중 처음 어긋나는 경계를 찾아 수정한다. 테스트 문장을 짧게 바꾸는 것으로 원래 제약을 숨기지 않는다.

### C5. 전량 번역·검토·삽입

PoC 통과 후 선언한 자막 목록 전체로 확장한다. 화자와 맥락을 보며 번역하고, 인명·지명·말투·진행 힌트를 용어집과 대조한다. 초벌 번역을 최종 검토 완료로 간주하지 않는다.

빌드는 미번역 대상, 미할당 음절, 보호 토큰 변경, 허용 길이 초과, 잘린 글리프, 잘못된 포인터를 실패로 처리한다. 인코더와 폰트 빌더는 같은 매핑표를 사용한다.

예정 산출물: `manifests/text_map.json`, `workspace/tables/`, `workspace/fonts/`, `workspace/translation/`, `docs/TEXT_ENGINE.md`, `docs/FONT_BUDGET.md`, `docs/POC_SUBTITLES.md`, 원문 추출/검증/빌드 스크립트. 개별 형식은 소비 경로 확인 후 확정한다.

## 8. 실행 순서와 AI 작업 분담 단위

아래는 다른 AI에게 순차로 맡길 수 있는 업무 단위다. 현재 대화에서 별도 AI 작업을 실행한 것은 아니다. 한 AI가 모두 수행해도 같은 인계 기준을 적용한다.

| 순서 / 업무 | 선행 조건 | 할 일 | 인계 완료 기준 |
|---|---|---|---|
| 1 / 분석 AI | 기준 해시 일치 | A: 화면 목록, 타이틀·대표 자막 경로 확인 | 근거 있는 좌표·뱅크·소비자와 미확정 목록 |
| 2 / 타이틀 AI | 타이틀 경로 확정 | B1~B3: 원본 재구성, 한국어 시안, 대표 PoC | 재현 빌드 및 실제 타이틀·전환 검증 |
| 3 / 텍스트·폰트 AI | 자막 경로 확정 | C1~C4: 가역 추출, 수요/예산, 대표 자막 PoC | 원문 왕복 및 실제 한국어 페이지·진행 검증 |
| 4 / 번역·제작 AI | 해당 경로의 PoC 통과 | 전체 로고, 자막 전량 번역/검토 및 적용 | 대상 목록과 입력 자료의 누락 0 |
| 5 / 통합·QA AI | 타이틀·자막 개별 빌드 | 한 원본 기준으로 통합, 회귀와 차분 패치 검증 | 아래 최종 완료 기준 충족 |

타이틀 디자인과 자막 조사 자체는 분리할 수 있으나, 공동 ROM을 수동으로 덮어쓰며 합치지 않는다. 각 작업은 소스·변경 계획만 인계하고 **통합 빌드 한 곳**에서 적용한다. CHR 슬롯·PRG 영역 소유권이 겹치면 통합 전에 해결한다.

난도 예상: 타이틀은 타일 공유/배치가 해결되면 비교적 국소적인 작업이다. 자막은 문자 공간·페이지 제어·뱅크 공유에 따라 난도가 크게 달라진다. 현재는 문장 수와 소비 루틴이 미확인이라 일정·완료율을 숫자로 약속하지 않는다.

## 9. 통합 빌드와 완료 기준

### 9.1 재현·정적 검사

- 기준 원본 + 확정 번역 + 폰트/그래픽 원천 + 설정에서 같은 결과를 재생성한다.
- 입력 도구·폰트 버전, 소스·결과 해시, 빌드 ID와 명령을 기록한다.
- 원본 헤더·길이 변경은 필요성과 매퍼 지원 근거가 있을 때만 명시적으로 계획한다.
- 타이틀과 자막의 모든 변경이 Expected Write로 설명되고 충돌이 없다. 보호 그래픽·토큰·참조가 유지된다.
- 추출 대상 수 / 번역 대상 수 / 삽입 완료 수 / 미확정 수를 함께 보고한다. 조사하지 않은 항목을 분모에서 숨기지 않는다.

### 9.2 패치 적용 검사

- 차분 패치 형식과 도구를 정한 뒤 배포 패치를 생성한다. 단일 ROM용 BPS 또는 기존 프로젝트 환경의 검증 가능한 차분 형식을 검토한다.
- 보존된 원본의 새 복사본에 배포용 적용 절차 그대로 패치를 적용한다.
- 적용 결과 SHA-256이 빌드 결과와 일치해야 한다. 다른 원본은 명확히 거부하거나 사전 식별 검사에서 차단한다.
- `dist/`에는 차분 패치, 적용 방법, 지원 원본 해시, 변경 범위, 알려진 제한만 넣는다. 전체 ROM은 넣지 않는다.

### 9.3 실행·시각 QA

| 검사 범위 | 확인할 것 |
|---|---|
| 타이틀 | 콜드 부팅, 대기/애니메이션, 시작 안내, 시작 입력, 리셋/복귀 |
| 모든 자막 장면 | 원문과의 항목 대응, 오역·누락, 받침/기호, 줄 끝·박스 경계 |
| 페이지/입력 | 빠른 넘김, 대기, 자동 진행, 이전 글자 지우기, 이벤트 연결 |
| 조건 분기 | 실제 존재하는 선택·캐릭터·진행 조건별 문구 및 접근 경로 |
| 공유 그래픽 | 캐릭터, 배경, 숫자, 점수 등 수정 타일의 다른 소비자 |
| 전체 진행 | 선언한 대상 장면을 모두 거치고 엔딩까지 진행; 정지·새 그래픽 손상 없음 |
| 환경 | 검증 ROM 해시, 에뮬레이터 경로/버전, 가능하면 두 번째 독립 에뮬레이터 대조 |

원본에 없는 기능은 QA 항목을 억지로 만들지 말고 ‘해당 없음’의 근거를 적는다. 두 번째 에뮬레이터나 실기 검증을 못 했으면 한계를 적고 수행한 것처럼 보고하지 않는다.

**최종 완료**는 타이틀과 선언한 인게임 자막 전체가 실제 장면에서 한국어로 읽히고, 진행·화면 회귀가 없으며, 배포 패치를 원본에 적용한 결과까지 검증한 상태이다. ‘타이틀 한 장 성공’, ‘빌드 성공’, ‘원본 왕복 성공’을 전체 한글화 완료로 부르지 않는다.

## 11. 현재 실행 가능한 명령

PowerShell에서 프로젝트 루트로 이동한다. 원본 확인은 Windows PowerShell 5.1 이상을 사용한다. 정적 CHR 조사에는 이번에 확인한 Python 3.12.10과 Pillow 12.3.0을 사용했다. 다른 환경에서는 의존성을 별도 확인한다.

```powershell
Set-Location -LiteralPath 'G:\Downloads\Korean Traslate Project\Games\Tiny Toon Adventures'
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\verify_source.ps1
python .\scripts\survey_rom.py --output .\extracted\chr\survey_20261001
```

위 두 명령만 현재 구현되어 있다. 이 계획서에 등장하는 추출기·삽입기·빌드기·QA 기록은 이후 제작할 산출물이다. 없는 명령을 실행된 것처럼 기록하지 않는다. `survey_rom.py`는 ROM을 읽고 지정 출력 폴더에 분석 자료를 쓰며, 같은 출력 폴더의 기존 분석 결과를 다시 생성한다. 과거 결과를 보존해야 하면 새 출력 폴더를 지정한다.

## 15. 작업 7 — 현재 대사 폰트 크기

원본 코드와 새 콜드 부팅 캡처로 글자 칸 8×8px, 대사 영역 16열×7행(128×56px)을 확인했다. 첫 한글 표시 PoC는 이 크기를 기준으로 한다. 8×16px 또는 16×16px로 확장하려면 출력 코드와 페이지 조판을 변경해야 한다. [폰트 크기 조사](FONT_SIZE_SURVEY.md)에 크기별 수용량·활성 CHR·재현 명령을 기록했다. 이 조사는 한글 글리프 공급·삽입·가독성을 검증한 결과가 아니다.

## 16. 작업 8 — 지정 폰트로 첫 대사 삽입

Galmuri7 PNG를 등록해 셜리 자기소개 `JP_175A9` 한 블록의 가시성·대표 E2E를 통과했다. [대사 삽입 PoC](POC_DIALOGUE.md)에 코드 배정·CHR 확장·원래 페이지 타이밍 보정·재현 명령을 기록했다. 첫 대사 밖 샘플 회귀는 없고 기존 한글 타이틀 004를 보존한다. 전체 수요 156종 / 항목별 최대 34종에 맞춘 페이지별 공급·대사 재배치·나머지 21블록·전체 장면 QA는 다음 구현 범위다.
