## 실측 근거

- CPU `$B280` / ROM 파일 `0x17290`에서 열 `$07AA`를 1 증가시킨다. 열이 `$14`(20)이 되면 4로 복귀하고 행 `$07AB`를 1 증가시킨다. 행이 `$0B`(11)가 되면 4로 복귀한다. 따라서 열 4–19, 행 4–10의 16×7 타일 영역이다. 영역 끝을 넘으면 첫 줄로 돌아가므로 페이지 처리는 별도로 필요하다.
- CPU `$B2CF` / 파일 `0x172DF`의 PPU 전송 버퍼 작성은 타일 수 1을 쓴다. 타일 주소는 `$2000 + 32×(행+$07DF) + (열+$07DE)`이며 글자마다 네임테이블 항목 하나를 쓴다.
- Mesen 2.1.1 원본 콜드 부팅, Start 입력만 사용해 프레임 840·960·1200·1440을 새로 확보했다. A를 누르지 않아 안내 문장을 기다렸다. ROM/RAM 쓰기·저장 상태 사용은 없다. 종료 0.
- 프레임 840에서 원점 보정 `$07DE/$07DF=0/0`, 배경 패턴 주소 `$0000`이다. 대사 영역의 화면 좌표는 `[32,160)×[32,88)`이다.
- 런타임 PPU `$0000–$03FF`는 CHR 상대 `0x1E000` / ROM `0x3E010`, `$0400–$07FF`는 CHR 상대 `0x1A800` / ROM `0x3A810`과 바이트 단위로 일치한다. 각각 1KiB 뱅크이며 화면 전체 폰트 뱅크의 가용 용량을 뜻하지 않는다.
- 추출 문자표 97개를 실제 활성 2bpp 타일로 해석했다. 타일당 16바이트, 8×8px이고 잉크 외곽의 최대 크기도 8×8px이다. 원본 `あ`, `か`, `ハ`는 7×8px이다. 원본 폰트를 7×7px라고 가정하면 안 된다.

원본 [프레임 840](../qa/dialogue/font_geometry_001/frame_0840.png), [프레임 1440](../qa/dialogue/font_geometry_001/frame_1440.png), [영역 격자 표시](../qa/dialogue/font_geometry_001/text_grid_annotated.png), [수치·바이트·해시 보고서](../qa/reports/font_size_final_2026-10-01.json)를 보관한다. NES 배경 타일의 8×8px 구조는 [NESdev PPU 명세](https://www.nesdev.org/NESDoc.pdf)도 설명한다. 게임의 창 크기와 출력 동작은 위 ROM 및 실행 실측으로 판정했다.

## 한글 크기별 적용 조건

| 글자 칸 | 현재 창의 산술상 수용량 | 글자당 타일 | 필요한 변경 |
|---|---|---|---|
| **8×8px** | **16자×7줄** | 1 | 현재 글자 크기·좌표 증가 방식 유지 가능. 한글 인코딩·타일 공급·조판은 별도 구현 |
| 8×16px | 16자×3줄 | 2 | 두 타일 출력, 행 간격, 지우기, 줄바꿈·페이지 재배치 |
| 16×16px | 8자×3줄 | 4 | 네 타일 출력, 열/행 간격, 지우기, 줄바꿈·페이지 재배치 |

확장 크기의 수용량은 현재 128×56px 영역을 유지한 계산이다. 확장 엔진을 구현하거나 한국어로 실행 검증한 결과는 아니다. 3줄을 사용하면 세로 8px가 남는다. 원문의 빈 줄까지 그대로 유지할 수 있다는 뜻도 아니다.

12×12px는 타일 하나에 들어가지 않는다. 16×16px 칸 안에 12×12px 잉크로 넣으면 8자×3줄이다. 실제 12px 간격으로 조판하려면 타일 사이 글리프 합성 등 별도 출력 구조가 필요하며 이번에는 조사·구현하지 않았다.

## 다음 삽입 설계에 적용할 판단

첫 한글 표시 PoC는 **8×8px 비트맵 칸**을 기준으로 한다. 7×7px 잉크와 1px 여백은 선택 가능한 설계지만 받침과 겹받침의 가독성은 실제 한국어 표시로 확인해야 한다. TTF를 단순히 8px로 래스터화해도 글리프가 8×8 칸 안에 맞는다고 보장할 수 없으므로 최종 비트맵 외곽을 검사한다.

현재 번역 수요는 고유 한글 156종 / 공백·기호·영문 포함 170종, 항목별 최대 한글 34종이다. 크기 8×8px가 맞는 것과 필요한 모든 글자를 공급할 수 있는 것은 별개다. 조사한 97개 기존 문자 코드는 빈 슬롯이 아니며 인접 그래픽도 보호 대상이다. 페이지별 CHR 뱅크 공급 또는 문자 코드/출력 방식 변경을 다음 PoC에서 정해야 한다.

`JP_17764`의 둘째 줄은 18문자다. 8×8px라도 현재 16열을 넘으므로 문구를 보존한 줄바꿈·페이지 설계가 필요하다. 8×16px/16×16px는 다른 번역문도 새로 페이지를 나누어야 한다.
